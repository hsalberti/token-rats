# Ongoing product conversations

Alberti publishes manually. The aim is recurring useful examples and responses. Every post discloses that he maintains Token Rats. This document is a queue of ideas, not an automated posting schedule.

## Weekly rhythm

| Day | Material | Place | Evidence to record |
| --- | --- | --- | --- |
| Monday | One real setup change, including what was removed | LinkedIn and a public Token Rats version | Post URL, replies, setup saves |
| Tuesday | Answer questions from the prior week | Original discussion threads and GitHub issues | Actual questions and fixes |
| Wednesday | “Tried it / dropped it” setup exchange | r/TokenRats weekly thread once created | Shared version links and useful notes |
| Thursday | A parser, model, or coordination implementation lesson | A relevant tool community, subject to its rules | Technical write-up and reproducible examples |
| Friday | Small release notes with one concrete change | GitHub release/discussion; optional opt-in email after email activation | Release URL, actual adoption/feedback |

Do not publish a filler post to satisfy the calendar. A useful reply can be the week's contribution. HN submissions are occasional significant releases; avoid resubmitting the same product every week.

## Places and what to bring

- **r/TokenRats:** founder-owned setup exchange and longer conversations. “Which instruction did you remove this week, and why?” Pin a link to the public setup version. Subreddit creation remains Alberti's task.
- **r/ClaudeCode:** use the current showcase thread for promotional material. Share a real Claude workflow change and ask about one specific design choice. [Community](https://www.reddit.com/r/ClaudeCode/).
- **r/ChatGPTCoding:** use the current self-promotion thread. Explain your affiliation and which tools the setup uses. [Community](https://www.reddit.com/r/ChatGPTCoding/).
- **OpenCode communities:** an actual local-source counting lesson or custom handler example. [r/opencodeCLI](https://www.reddit.com/r/opencodeCLI/) and [r/opencode](https://www.reddit.com/r/opencode/). Verify current rules/flair before posting.
- **Show HN:** the substantial setup-history release, once the founder is available to answer. [Submission form](https://news.ycombinator.com/submit), [Show HN guidance](https://news.ycombinator.com/showhn.html), [HN guidelines](https://news.ycombinator.com/newsguidelines.html). Link something visitors can inspect and try without starting a sales conversation.
- **GitHub:** changelog, issues, and relevant discussions in the project's own repository. For another project's discussion, contribute a directly relevant implementation or answer; avoid unsolicited promotion in unrelated issues.
- **Indie Hackers:** a concrete build/retention lesson when real data exists. [Community](https://www.indiehackers.com/). Check group rules before publishing.
- **Personal X/Bluesky accounts:** a short diff or setup card with a permanent version link. Use the fuller explanation on the profile or linked Reddit thread.

The dated thread URLs in roadmap.md are research snapshots. Open each venue on posting day to find its current thread and rules; do not present a stale link as today's recommendation.

## Show HN draft

Title: Show HN: Token Rats — version and rate the agent setups you try

Link: https://github.com/hsalberti/token-rats

I maintain Token Rats. It started with local coding-agent usage tracking. I’ve added a history for the instructions, tools, models, and subscriptions people actually use.

You can save private versions, inspect diffs, restore an older setup, or share a version publicly. Follow someone to see new versions. If you try one, you can keep it on a Want to try / Trying / Using / Tried / Dropped shelf and give that exact version a star rating with a short note.

Usage tracking and leaderboards are still available. We display usage separately; the app does not infer that a configuration change caused a token change.

Here is my public example: https://tokenrats.com/u/hsalberti

I’d value feedback on whether the saved bundle has enough context to adapt a setup, and what you need to remember an experiment you abandoned.

## Weekly Reddit prompt

What did you try in your agent setup this week that you decided to keep—or remove?

A small before/after excerpt is enough. Add the tools and models, what you wanted from the change, and why it fit or didn’t fit your work. A Token Rats version link is welcome, but an account is not required to join this discussion. I maintain Token Rats and want the examples to be useful even when an experiment fails.
